# Тест-план автоматизации тестирования мобильного приложения "Мобильный хоспис"

## 1. Объект тестирования
Мобильное приложение «Мобильный хоспис» (Android)

## 2. Цели автоматизации
- Проверка критически важного функционала приложения
- Сокращение времени регрессионного тестирования
- Обеспечение стабильности приложения при изменениях

## 3. Объём автоматизации (что будет покрыто автотестами)

### 3.1. Модуль авторизации
- Успешный вход с валидными данными (login2/password2)
- Вход с неверным паролем
- Вход с пустыми полями
- Выход из аккаунта

### 3.2. Модуль навигации
- Открытие экрана «About»
- Открытие экрана «Our Mission»
- Открытие главного экрана после авторизации

### 3.3. Модуль новостей
- Отображение списка новостей
- Клик по новости (открытие полного текста)
- Создание новой новости
- Редактирование существующей новости
- Удаление новости
- Фильтрация новостей по категории/дате
- Сортировка новостей

### 3.4. Модуль цитат (Our Mission)
- Открытие экрана с цитатами
- Разворачивание/сворачивание цитаты

## 4. Что НЕ будет покрыто автотестами
- Регистрация нового пользователя (не предусмотрена в приложении)
- Работа с комментариями к новостям
- Офлайн-режим

## 5. Инструменты
| Инструмент | Назначение |
|------------|------------|
| Android Studio | Среда разработки |
| Espresso | UI-тестирование |
| JUnit 4 | Фреймворк для тестов |
| Page Object Pattern | Организация кода |
| IdlingResource | Ожидание загрузки данных |

## 6. Архитектура тестов
| Ui |
- pages/ # Page Object классы (экраны)
- tests/ # Тестовые классы (оканчиваются на Test)
- utils/ # Вспомогательные классы (ожидания, helpers)


## 7. Этапы автоматизации
1.  Анализ функционала
2.  Составление чек-листа
3.  Составление тест-кейсов
4.  Написание автотестов
5. Подготовка отчётов
6. Поддержка и рефакторинг

## 8. Критерии успешной автоматизации
- 100% тест-кейсов из чек-листа автоматизированы
- Тесты стабильно проходят на эмуляторе API 33
- Код соответствует Page Object Pattern
